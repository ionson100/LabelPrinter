# LabelPrinter — печать этикеток GS1 через APLINK (MRX72e / HRX)

WPF (.NET Framework 4.8), PostgreSQL + Redis, протокол **APLINK XML Protocol 2.24**
(UBS / MRX72e-HRX).

Задача: программа берёт уникальные коды из PostgreSQL, держит буфер в Redis,
по одному отдаёт код принтеру в формат `demo` (переменная `code`) и следит за
счётчиком напечатанных этикеток — принтер печатает по внешнему триггеру.

---

конфликтов версий, и подключить в том числе из .NET 5–9, MAUI или Avalonia.

## Как подключить к своему приложению

Нужно реализовать один интерфейс — `ICodeSource` (откуда берутся коды) и
подписаться на журнал. Больше ничего знать про протокол не требуется.

```csharp
using LabelPrinter.Core.Abstractions;
using LabelPrinter.Core.Configuration;
using LabelPrinter.Core.Diagnostics;
using LabelPrinter.Core.Runtime;

// 1. Журнал: по умолчанию библиотека молчит.
Log.Sink = new DelegateLogSink(m => Console.WriteLine(m.Line));

// 2. Движок
var engine = new PrintEngine(new PrintRuntimeSettings(), new CodeFormatSettings());

// 3. Откуда брать коды — единственное, что решаете вы
engine.CodeSource = new MyCodeSource();   // ваша база, файл, очередь…

// 4. Принтеры
engine.Printers.Add(new PrinterSettings("Принтер 1", "192.168.1.10", 4100));

await engine.StartAsync(ct);              // подключиться
await engine.StartPrintingAsync(ct);      // печатать
await engine.StopPrintingAsync(ct);       // остановить
```

`ICodeSource` — пять методов:

```csharp
public interface ICodeSource
{
    Task<int>  GetBufferCountAsync(CancellationToken ct);
    Task<int>  EnsureBufferAsync(int capacity, int threshold, CancellationToken ct);
    Task<string> TakeAsync(CancellationToken ct);      // null — кодов больше нет
    Task<long> GetRemainingAsync(CancellationToken ct);
    Task ClearAsync(CancellationToken ct);
}
```

Готовый пример — в `samples/LabelPrinter.Core.Sample`, он собирается под .NET 9 и
печатает без единой строки протокола:

```
samples\LabelPrinter.Core.Sample\bin\Release\net9.0\LabelPrinter.Core.Sample.exe 192.168.1.10 4100 demo code
```

Готовый пример источника кодов на PostgreSQL + Redis — `PostgresRedisCodeSource`
в приложении.

### Постоянные поля этикетки

Нужно для маркировки по «Честному знаку», где в коде много элементов, а меняется
только серийный номер: дата, масса, номер партии и GLEI одинаковы на весь тираж.

`SetFixedVariables` принимает словарь «имя поля в шаблоне → значение»:

```csharp
engine.SetFixedVariables(new Dictionary<string, string>
{
    { "91", "PART-000123" },   // номер партии
    { "92", "2500"         }  // масса нетто
});
```

Дополнительно: `engine.FixedVariables` — текущий набор, только чтение;
`engine.ClearFixedVariables()` — убрать все поля. Вызов разрешён и во время печати:
изменение применится со следующей этикетки (удобно менять, например, массу на
новой паллете).

**Про «задать один раз» важно понимать верно.** Метод вызывают один раз перед
печатью, но значения уходят **в каждой** `SET_PRINTING_FORMAT` — протокол требует
полный набор полей в каждой этикетке:

> *It is allowed to use as many VARIABLE tags as required to reach the number of
> variables in the label.*

Спрятать значения в принтере штатного способа нет:

* `useCache=True` кэширует **макет** формата, а не значения, и требует, чтобы
  формат уже загружали в принтер вручную;
* `SET_VARIABLE_BATCH` грузит **список** значений заранее (`value1|value2|valueN`),
  принтер расходует их последовательно, и для загрузки принтер должен стоять на паузе.

Если темп печати станет упираться в сеть, `SET_VARIABLE_BATCH` — естественный
следующий шаг; команда реализована в `Protocol/Commands.cs`, но пока не задействована.

Поле с тем же именем, что и переменная с кодом, игнорируется с предупреждением в
журнале — иначе все этикетки тиража получили бы одинаковый серийный номер.

dotnet build LabelPrinter.sln -c Release

## Формат кода

По заданию шаблон кода:

```
01{GTIN}21{R1}{GS}93{R2}
```

| Часть | Значение | Пример |
|---|---|---|
| `01` | AI — GTIN-14, фиксированный | `02345678987654` |
| `21` | AI — серийный номер, 6 случайных символов | `0BH6SS` |
| `0x1D` | **разделитель групп** (FNC1 в символике) | непечатаемый байт |
| `93` | AI — 4 случайных символа | `93` + `udtI` |

Готовый код — 31 байт, например:

```
0102345678987654210BH6SS␝93udtI
```

Разбор для журнала и формы — разделитель показан как `<gr>`:

```
(01)02345678987654(21)0BH6SS<gr>(93)udtI
```

* **Разделитель групп обязателен.** AI(21) имеет переменную длину, поэтому без FNC1
  получатель прочитает один длинный элемент вместо двух. Убирать `{GS}` из шаблона нельзя.
* Случайные блоки берутся из криптографического ГПСЧ, алфавит 62 символа
  (`0-9A-Za-z`), 10 случайных позиций → ≈ 8.4·10¹⁷ комбинаций при потребности в 10 000.
* Уникальность гарантируется уникальным индексом по `"Code"` в базе.
* При разборе кода разделитель имеет приоритет над поиском следующего AI: внутри
  случайных символов легко встретить пару цифр, совпадающую с номером другого AI
  (например `12` внутри `(21)`), и без этого правила разбор «рассыпался» бы.

### ⚠ Контрольная цифра GTIN-14 не сходится

Указанный в задании GTIN `02345678987654` **не проходит проверку контрольной цифры**:
расчётная последняя цифра — `8`, а в шаблоне `4`.

```
02345678987654
             ^ должно быть 8
```

Программа **не меняет** это значение (оно задано вами и зашито в шаблон на принтере),
но пишет предупреждение в журнал при каждом запуске. Часть сканеров такие коды не примет.
Если это опечатка — поправьте `Gtin14` в `settings.json` на `02345678987658`.

## Таблица `Codes`

Имя таблицы регистрозависимое — совпадает с именем класса модели.

```sql
CREATE TABLE "Codes" (
    "Id"        uuid        NOT NULL,
    "Code"      varchar(64) NOT NULL,
    "IsPrinted" boolean     NOT NULL DEFAULT false,
    CONSTRAINT "PK_Codes" PRIMARY KEY ("Id")
);
CREATE UNIQUE INDEX "IX_Codes_Code"       ON "Codes" ("Code");
CREATE INDEX       "IX_Codes_IsPrinted" ON "Codes" ("IsPrinted");
```

Выдача кодов — одной атомарной транзакцией:

```sql
WITH picked AS (
    SELECT "Id" FROM "Codes"
    WHERE "IsPrinted" = false
    ORDER BY "Code"
    LIMIT @count
    FOR UPDATE SKIP LOCKED      -- не блокирует чужие строки
)
UPDATE "Codes" c SET "IsPrinted" = true
FROM picked p WHERE c."Id" = p."Id"
RETURNING c."Code";
```

`SKIP LOCKED` — то, что позволяет безопасно запустить несколько копий программы
(или перезапустить её посреди печати) и не выдать один код дважды.

> **Следствие для учёта:** код помечается `IsPrinted = true` в момент выдачи из базы,
> то есть до фактической печати. Если принтер застрял или этикетка не вышла,
> код считается израсходованным — это прямо следует из задания. Такие случаи
> видно в журнале как «код был заряжен, но не напечатан».

## Буфер в Redis

| Параметр | По умолчанию | Где |
|---|---|---|
| Вместимость | 100 | `BufferSize` |
| Порог долива | 10 | `BufferRefillThreshold` |
| Ключ | `labelprinter:buffer:{idПринтера}` | `AppSettings.BufferKey` |

Поведение ровно по заданию:

* буфер пуст → берём из базы 100 кодов и помечаем их напечатанными;
* остаток упал до 10 → доливаем до 100, то есть добираем 100 − 10.

Ключ привязан к принтеру, поэтому при нескольких принтерах каждый получает
**свои** коды и они не пересекаются.

Порядок выдачи — FIFO: коды кладутся в начало списка (`LPUSH`), забираются с конца (`RPOP`).

**Резервный режим.** Если Redis недоступен, программа пишет в журнал ошибку и
переходит на буфер в памяти процесса — печать продолжает работать, но коды
не переживут перезапуск. Это отмечено в журнале явно.

## Протокол APLINK

Обмен идёт по TCP. Каждое сообщение обрамлено служебными байтами:

```
начало: 0x27 0x01 0x27 0x02
конец : 0x27 0x03 0x27 0x04
```

За раз разрешено **одно** сообщение, внутри `<PROTOCOL> … </PROTOCOL>`.
Значения атрибутов в ответах приходят **без кавычек** (`Value=OK`), поэтому ответы
разбираются регулярными выражениями — обычный XML-парсер здесь неприменим.

Используемые команды:

| Команда | Назначение |
|---|---|
| `GET_COUNTER` | количество напечатанных этикеток задания (`CUSTOM_COUNTER`) |
| `SET_PRINTING_FORMAT` | передать код в переменную формата и поставить в печать |
| `SET_PRINTING_STATUS` | `Yes` — печать, `No` — пауза |
| `GET_PRINTING_STATUS` | готов ли принтер |
| `PRINT_CONFIG` / `<TRIGGER>` | выбор триггера: `photocell` / `distance` / `timer` |
| `GET_FORMAT_LIST` | какие форматы загружены в принтер |
| `GET_ERROR_LIST` | активные ошибки |
| `GET_PRINTER_INFO` | модель, серийник, версии |
| `QUEUE_STATUS`, `QUEUE_CLEAR` | очередь печати |

Реализованы также `QUEUE_ENABLE/DISABLE`, `GET_PRINT_CONFIG`, `GET_VERSIONS`,
`SET_VARIABLE_BATCH` / `SET_VARIABLE_BATCH_CLEAR` / `GET_VARIABLE_BATCH_COUNT`,
`SET_DATE_OFFSET`, `GET_PRINTING_VARIABLES`, `CMD_DELETE_FORMAT` — в `Protocol/Commands.cs`.

### Рабочий цикл печати

```
Старт  →  GET_COUNTER, запоминаем CUSTOM_COUNTER как базу
         ↓
       взять код из буфера (пусто → долить из БД)
         ↓
       SET_PRINTING_FORMAT Format=demo <VARIABLE Name=code Value=…>
       SET_PRINTING_STATUS Yes          ← принтер «готов», ждёт триггера
         ↓
       опрос GET_COUNTER
         ↓
       счётчик вырос  →  следующий код
```

Потеря связи обрабатывается в рабочем цикле: соединение закрывается, лампочка
становится красной, через `ReconnectDelaySeconds` идут повторные попытки.
Печать при этом не падает — когда связь вернётся, принтер продолжит.

Счётчик принтера только растёт, поэтому обработки уменьшения нет. Базовое значение
снимается один раз при старте печати — иначе счётчик, накопленный до запуска
программы, попал бы в статистику сеанса.

## Настройки (`settings.json`)

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `ConnectionString` | `Server=localhost;Port=5432;Database=printer;User Id=postgres;Password=postgres;` | PostgreSQL |
| `RedisConnectionString` | `localhost:6379,…` | Redis |
| `InitialCodeCount` | `10000` | до скольки кодов держать базу |
| `BufferSize` | `100` | вместимость буфера |
| `BufferRefillThreshold` | `10` | когда доливать |
| `TestPrinterMode` | `false` | тестовый принтер вместо реального |
| `TestPrintIntervalSeconds` | `5` | интервал печати в тестовом режиме |
| `PollIntervalMs` | `100` | как часто опрашивать счётчик (и пауза перед следующим кодом) |
| `ReconnectDelaySeconds` | `5` | пауза перед переподключением |
| `PrinterTimeoutMs` | `5000` | таймаут обмена с принтером |
| `TriggerMode` | `photocell` | внешний триггер |
| `Gtin14` | `02345678987654` | фиксированная часть кода |
| `CodeTemplate` | `01{GTIN}21{R1}{GS}93{R2}` | шаблон кода; `{GS}` — разделитель групп |
| `RandomPart1Length` / `RandomPart2Length` | `6` / `4` | длины случайных блоков |
| `CodeAlphabet` | `0-9A-Za-z` | алфавит |
| `GroupSeparatorAsEntity` | `false` | передавать 0x1D как `&#x1D;` вместо сырого байта |

> `GroupSeparatorAsEntity` — запасной вариант. Формально XML 1.0 не допускает
> управляющий символ внутри значения атрибута, поэтому строгий парсер может
> отвергнуть команду с сырым `0x1D`. По умолчанию шлём сырой байт; если принтер
> ответит ошибкой — переключите на `true` в `settings.json`.

> **Смена шаблона не меняет уже залитые коды.** Строки в таблице остаются в старом
> формате и уйдут на этикетки. Программа предупредит об этом в журнале; чтобы
> перейти на новый формат, нажмите **«Очистить буфер»**.

Список принтеров — массив `Printers`: `Id`, `Name`, `Host`, `Port`, `Enabled`,
`FormatName` (`demo`), `VariableName` (`code`), `BoardId`, `UseFormatCache`.

> `UseFormatCache` включает `useCache="True"` в `SET_PRINTING_FORMAT`. По руководству
> принтер требует, чтобы формат **уже был загружен в него вручную**, иначе вернёт
> ошибку. По умолчанию выключено.

### Граница между библиотекой и приложением

Библиотека **не знает** про PostgreSQL и Redis: она умеет обеспечивать принтер
следующим кодом и следить за темпом печати. Приложение реализует `ICodeSource`
и отвечает за хранение.

Один источник на все принтеры: коды не пересекаются, потому что выдача из базы
помечает их `IsPrinted = true` в одной транзакции (`FOR UPDATE SKIP LOCKED`).

## Что стоит проверить на реальном принтере

1. **Разделитель групп.** По умолчанию `0x1D` уходит сырым байтом внутри
   `Value="…"`. Формально XML 1.0 такое значение в атрибуте не допускает. Если
   принтер ответит ошибкой на `SET_PRINTING_FORMAT` — поставьте в `settings.json`
   `"GroupSeparatorAsEntity": true`, и будет уходить `&#x1D;`.
2. **Порт.** По умолчанию 4100. В инструкции к вашей модели может быть другой —
   проверьте и поправьте в настройках принтера.
3. **Имя формата и переменной.** Программа ждёт формат `demo` с переменной `code`.
   Проверить можно командой `GET_FORMAT_LIST` — она выводит все форматы в журнал.
4. **Триггер.** По умолчанию `photocell` (внешний). Если печать идёт не по сигналу
   датчика, поменяйте `TriggerMode` на `timer` или `distance`.
5. **Пауза при печати.** Формат ставится с `Quantity="1"` — принтер печатает одну
   этикетку и ждёт следующего задания. Это соответствует схеме «одна этикетка —
   один код»; если принтер уходит в паузу агрессивнее, возможно, потребуется
   очередь принтера через `SET_VARIABLE_BATCH` — команда реализована, но не
   задействована.
6. **Темп.** По умолчанию опрос каждые 100 мс, значит потолок ≈ 10 этикеток/с на
   принтер. Если линия быстрее — снижайте `PollIntervalMs` в форме, либо переходите
   на очередь принтера / UDP-события (`SET_EVENTS_CONFIG`), тогда принтер сообщает
   о печати сам и опрос не нужен.
